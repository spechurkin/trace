# Investigation Creator

Встроенный модуль создания и проверки расследований. Реализация полностью локальная и детерминированная, без моделей,
сетевых запросов и сервисов ИИ.

## Подключение

Модуль хранится целиком в этой папке. `engine.ts`, `schema.ts` и `contracts.ts` не импортируют приложение, Electron или
хранилище. `Assistant.tsx` — интерфейс React с собственными стилями и переводами. Зависимости: React и Zod; сборщик
должен поддерживать TypeScript, CSS и JSON.

Хост передаёт `board`, `nodes`, `locale`, `mode` и обработчики сохранения. Через `renderNodeEditor` он подключает
редактор нод. При сохранении модуль возвращает план и ноды доски, а хост отвечает за их запись, изображения, папки и
ограничение размера библиотеки. Пример адаптера — `src/InvestigationCreator.tsx`; поле `Club.investigation`
необязательно, поэтому старые расследования продолжают открываться.

```tsx
<InvestigationAssistant
  board={board}
  nodes={nodes}
  locale="ru"
  mode={board.characterIds.length ? 'audit' : 'create'}
  initialStep={board.characterIds.length ? 'completeness' : 'crime'}
  onSave={(plan, members, close) => saveToHost(plan, members, close)}
  onClose={returnToBoard}
  renderNodeEditor={renderHostNodeEditor}
/>
```

Инструктор открывается кликом по центральному Виновному на пустой доске. Если есть хотя бы одна другая нода, открывается
проверяющий с отчётом и инструментами исправления. При соединении ветвей Виновный остаётся допустимой вершиной дерева.
Переходы инструктора и кнопки сохранения записывают черновик. Возврат на доску также сохраняет его.

## Семь инструментов

1. Конструктор преступления: событие, пострадавший, ответственные, мотив, способ и обстоятельства; создание и
   редактирование нод через адаптер.
2. Матрица улик: поддержка и опровержение выводов, достоверность, независимые источники, авторская истина и знания
   игроков.
3. Хронология: интервалы начала, длительность, отдельные периоды, порядок, алиби и минимальное время пути.
4. Достижимость: точки входа, альтернативные способы обнаружения и обязательные условия, достижение развязок.
5. Тупики: бесполезные окончания ветвей и циклы, критические зацепки, потеря которых разрушает путь или обязательное
   доказательство.
6. Ложные версии: подозреваемый, мотив, кажущееся подтверждение и доступное опровержение. Предложения составляются
   только из явно связанных участников, мотивов и ролей улик; добавление подтверждает автор.
7. Полнота: потерянные ссылки, неиспользуемые улики, события без последствий, недоступные места и незаполненные вопросы.

Для выбранных мест поиска и мест с назначенными уликами предлагается минимум три **разные** улики. Несколько ролей одной
улики считаются один раз. Меньшее количество допустимо: рекомендация имеет уровень `info`, не блокирует сохранение и не
требует выдумывать содержание. Из неё можно сразу создать улику для соответствующего места.

## Алгоритмы и пределы проверки

- Достижимость — прямой вывод до неподвижной точки на ориентированном гиперграфе. В одном способе обнаружения условия
  соединены AND, разные способы — OR. Свидетельства считаются по уникальным нодам; спорные источники не доказывают
  факты. Авторская истина и визуальные ветви не дают игрокам знания автоматически.
- Замкнутые цепочки — итеративный алгоритм Косарайю. Полезность ветвей — обратное распространение от развязок,
  обязательных выводов и опровержений. Критические ноды — повторный расчёт при исключении каждой ноды с учётом порогов
  доказательства.
- Хронология — Simple Temporal Network и алгоритм Беллмана — Форда с указанием записей отрицательного цикла. Интервалы
  уточняются кратчайшими путями. Присутствия в разных местах проверяются как альтернативы порядка; совместная
  выполнимость — ограниченный поиск с отсечениями по временной сети.
- Для больших планов дорогой перебор ограничен: 2 000 000 оценочных операций и 1024 ветви поиска временных вариантов.
  При исчерпании бюджета отчёт явно сообщает, что проверка не завершена, и не объявляет структуру полностью проверенной.

Время задаётся в минутах относительно начала **своего периода**. Интерфейс принимает `23:00`, `1/02:16` для следующего
дня, отрицательные дни. Длительность, промежутки и время пути задаются в минутах; путь между парой мест трактуется
симметрично. Неизвестные даты старого дела не приравниваются к текущей ночи. Спорные времена остаются показаниями и не
превращаются в фактические ограничения.

Проверка опирается на явно введённую структуру. Она не интерпретирует художественный текст, не выводит мотивы или алиби
из описаний и не гарантирует смысловую непротиворечивость прозы. Пустые данные считаются неполнотой. Ошибки логики
допускают сохранение черновика; некорректный формат полей исправляется перед записью.

## Тестовый пример и проверки

Существующее расследование «Мёртвый свидетель» размечено в адаптере `src/demo-creator.ts`: точки входа, пути, роли улик,
ложные версии, ночь через полночь и отдельное старое дело. Неизвестные исполнители, места алиби и точные минуты не
придуманы. Рекомендации о недостающих уликах сохраняются там, где исходный пример содержит меньше трёх.

`engine.test.ts` проверяет этот пример и специально повреждённые варианты, AND/OR, пороги независимости, циклы, тупики,
алиби, время пути, перенос ссылок и рекомендации. `tests/desktop/creator.spec.ts` проверяет реальные окна Electron в
обеих локалях, выбор режима по наполнению доски, редактирование и сохранение после перезапуска.

```text
node node_modules/vitest/vitest.mjs run modules/investigation-creator
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build
node scripts/build-electron.mjs
node node_modules/@playwright/test/cli.js test tests/desktop/creator.spec.ts
```
